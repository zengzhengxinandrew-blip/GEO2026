# 样本库与采样可靠性修复（2026-10-01）

## 修复原因

- 同日采样会追加 JSONL。以前列表直接读取所有行、详情取第一行、总览重复计数，而部分指标取最后一行，口径不一致。
- 失败样本中保存的 `error` 是当时大模型的错误，之前弹窗把它当作详情接口读取错误，所以无法查看。
- Kimi 部分模型不接受固定的 `temperature=0.7`；现在省略该参数，使用模型默认值。
- 豆包的 `401 / AuthenticationError / API key format is incorrect` 是鉴权失败。需要在设置中填入该方舟账号完整有效的 API Key，程序不能修复无效凭据。
- 旧总览直接相减两天的提及率，未检查问题、引擎、模型与采样模式是否一致；没有引用来源还会被文案误解为引用率为零。

## 新行为

同日、同引擎、同问题 ID（无 ID 时用题目）、同轮次、同模式只采用最后一次记录，列表、详情和总览保持一致。不同轮次仍保留并标明。原始文件不会因浏览而被删除；人工删除一个逻辑样本时会同时移除它的旧副本，避免删除后旧记录重新出现。

任务结束或重新进入样本库时，页面会重新读取列表，并忽略任务运行前尚未返回的旧请求。列表与“查看”详情因此不会再出现一边显示采样失败、另一边已有成功答案的缓存错位。竞品只统计项目配置中、且答案按名称或别名实际点名的竞品；“其他品牌”“同行”等泛称不计入。

失败或没有答案的记录不会计为「未提及」。失败详情显示原始错误和下一步操作；401/403/400 会停止该引擎剩余请求，所有调用均失败时任务明确失败。

总览显示有效样本数。失败、配置引擎缺失、问题未采全或有效无提示样本少于 30 时标记为暂定，不直接比较两期升降。30 条是提示样本偏少的界面规则，不是统计显著性保证。只有题目、引擎、模型、轮次、模式、联网设置等匹配时，才显示描述性的提及率变化。旧记录没有模型信息时不推断其模型。

历史健康分仍使用当前阵地/内容/事实记录重新计算，界面明确标注该限制；它不等于当时保存的完整健康分快照。即使条件一致，AI 回答仍有随机性，单日小幅升降不能直接当成品牌改善或恶化。

## 更新后操作

### 密钥保存与重启

页面可编辑的引擎密钥、模型和发布凭据，以 `GEOLOOK_ENV_FILE` 指向的文件为准
（Docker 默认 `/data/.env`，本地默认项目 `.env`）。文件里已有的这些设置会覆盖
容器启动时注入的旧值；文件中没有的项继续使用环境变量。旧版保存的文件无需迁移。
端口、登录令牌、数据目录等部署设置仍保持非空环境变量优先。

清除 Key 会保存 `变量名=` 的空值标记，防止旧容器凭据在重启后重新启用；不要手动
删除这个标记，否则会恢复使用外部环境值。保存采用原子替换，成功后才更新进程环境。
新启动的任务使用新配置；已经运行的任务不会被中途替换密钥。无需另外执行 `export`。
历史失败记录不会自动重跑，已泄露或被平台撤销的密钥仍需重新生成并在页面保存。

### 采样

1. 部署成功后强制刷新网页，重复记录自动按统一口径展示，无需删除客户数据。
2. 设置 → 引擎与密钥 → 豆包，重新粘贴火山方舟的 API Key。不要填资源 ID、接入点 ID 或其他产品密钥。只显示「已配置」不代表鉴权已通过。
3. 重新运行 AI 答案采样；旧日期的失败记录会继续保留为历史。当天同条件重试成功后会展示最新答案。
4. 固定问题库、模型及轮次后持续观察；不要为让分数稳定而反复重跑挑选高分。

验证使用临时项目数据与模拟供应商响应，包含真实本地 HTTP 详情请求和执行实际前端函数的测试；没有调用付费模型。服务器中的真实 Key 是否有效仍以更新后的真实采样结果为准。
